NPU 關鍵架構與技術：Magpie M5ANPU architecture and key techniques: Magpie M5A

雙發射 RV32IMF CPU 搭配 16×16 int8 GEMV NPU 的 SoC。已在 AMD ZCU104 FPGA 上以 150 MHz 實機執行 Gemma3-270M 聊天推論，並完成 TSMC 28HPC+ 邏輯合成。 An SoC pairing a dual-issue RV32IMF CPU with a 16×16 int8 GEMV NPU. It runs Gemma3-270M chat inference on an AMD ZCU104 FPGA at 150 MHz, and has been through TSMC 28HPC+ logic synthesis.

每拍 256 個 MAC 的 output-stationary 陣列Output-stationary array, 256 MACs per cycle
16 個 row 各負責一個輸出元素，每個 row 一拍做 16 個 int8 × int8 乘法，經 4 組部分和與加法樹累加成 int32。Each of 16 rows owns one output element and does 16 int8 × int8 multiplies per cycle, summed through 4 partial sums and an adder tree into int32.
權重雙緩衝Double-buffered weights
計算目前 16 列的同時預載下一批權重，MAC 陣列不必停下來等記憶體。The next batch of weights loads while the current 16 rows compute, so the MAC array never waits on memory.
直接讀 llama.cpp 的 Q8_0 權重Reads llama.cpp Q8_0 weights directly
硬體自行拆解 Q8_0 block（每 32 個 int8 權重配一個 fp16 scale），模型檔不需要另外轉檔。Hardware unpacks the Q8_0 block (one fp16 scale per 32 int8 weights), so the model file needs no conversion.
NPU 自己搬資料The NPU moves its own data
以最長 256 拍的 AXI burst 從 DDR 讀權重、把結果寫回 DDR，並與 D-cache 輪流共用同一個 AXI master。It reads weights from DDR in AXI bursts of up to 256 beats, writes results back to DDR, and shares one AXI master with the D-cache by round-robin.
硬體還原浮點 scaleFloating-point scale restored in hardware
每個 block 的 int32 內積在 NPU 內乘回權重與 activation 的 scale，輸出直接是 fp32。Each block’s int32 dot product is multiplied back by the weight and activation scales inside the NPU, so the output is fp32.

我們怎麼驗證How we verify

正確與否由比對結果決定，而不是「看起來對」或 lint 通過。 Correctness is decided by comparison results, not by “looks right” or a clean lint.

逐 commit 與 Spike 比對Per-commit lockstep with Spike

RTL 每一筆 commit 的結果都與 Spike ISS 對照，向量 CSR 也在比對範圍內。Every commit the RTL retires is compared against the Spike ISS, vector CSRs included.

逐位元的 golden 資料Bit-accurate golden data

矩陣運算對照 NumPy golden，推論結果對照 TFLM。換傳輸路徑不能改變任何一個位元組。Matrix math is checked against a NumPy golden and inference against TFLM. Changing the transport path may not change a single byte.

一行指令重跑Re-run with one command

核心流程只用開源工具：Verilator、Spike 與 RISC-V GCC。沒有執行過的 gate 不會標成通過。The core flow uses only open-source tools: Verilator, Spike and RISC-V GCC. A gate that has not run is never marked as passed.
